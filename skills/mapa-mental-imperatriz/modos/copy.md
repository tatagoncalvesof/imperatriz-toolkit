# Modo: COPY

## Quando usar

- Briefing de copy antes de escrever
- Mapeamento de oferta + persona + dor
- Análise pré-anúncio/VSL/página
- Reorganizar copy existente

## Estratégia

Mapa de copy é o **briefing visual** — força você a ter clareza ANTES de escrever uma palavra. Integra com `/briefing-copy-360`.

3 movimentos:

1. **Centro:** o produto/oferta
2. **Pilares de copy** (persona, dor, desejo, objeção, prova, oferta, mecanismo)
3. **Munição** (frases-prontas, dados, citações, provas)

## Hierarquia base — framework Imperatriz

```
NÍVEL 0: Produto/oferta
NÍVEL 1: 7 pilares
  ├── Persona
  ├── Dor
  ├── Desejo
  ├── Objeção
  ├── Prova
  ├── Mecanismo
  └── Oferta
NÍVEL 2: Detalhamento por pilar
NÍVEL 3: Frases/dados específicos
```

## Template completo

```
ROOT: <Produto/Oferta>
├── Persona
│   ├── Quem é
│   ├── Onde está (estado emocional)
│   ├── Linguagem que usa
│   └── O que já tentou
├── Dor
│   ├── Sintoma visível
│   ├── Causa raiz
│   ├── Custo de não resolver
│   └── Falsas soluções
├── Desejo
│   ├── Resultado tangível
│   ├── Identidade nova
│   └── O que vai poder fazer
├── Objeção
│   ├── "Não tenho tempo"
│   ├── "Não tenho dinheiro"
│   ├── "Já tentei"
│   └── "Não funciona pra mim"
├── Prova
│   ├── Cases (com números)
│   ├── Depoimentos
│   ├── Autoridade do criador
│   └── Estudos/dados
├── Mecanismo
│   ├── Nome próprio
│   ├── Como funciona (1 frase)
│   └── Por que único
└── Oferta
    ├── Stack de valor
    ├── Bônus
    ├── Garantia
    └── Preço + condições
```

## Adaptação ao input

- **Briefing 360 pronto:** importa direto, vira mapa estrutural do briefing
- **Apenas oferta:** infere persona/dor/desejo a partir do produto
- **Copy existente pra revisar:** mapeia o que JÁ TEM e o que FALTA
- **Múltiplas personas:** mapa por persona, não tudo junto

## Como usar o mapa pra escrever

Cada folha do mapa vira **1 frase ou bloco de copy**:

- Folha "Dor: Custo de não resolver" → bloco de agitação na página
- Folha "Prova: Case Maria 50k" → testimonial section
- Folha "Objeção: Não tenho tempo" → FAQ ou parágrafo específico
- Folha "Mecanismo: Nome próprio" → headline da seção do método

## Conexões cruzadas típicas

- Dor ↔ Desejo (dor inversa é desejo — ex: "perdido" → "claro")
- Objeção ↔ Prova (cada objeção precisa de prova específica)
- Mecanismo ↔ Diferencial (mecanismo único = razão de ser único)
- Persona ↔ Linguagem (persona define vocabulário usado)

## Integração com ecossistema

Quando finalizar o mapa, sugere automaticamente:

```
Próximos passos:
  → /headline-imperatriz (vira pilares em headlines)
  → /mecanismo-unico (estrutura o ramo Mecanismo)
  → /skill-pagina-vendas (constrói a página com base no mapa)
  → /voz-humana-br (humaniza o vocabulário)
```

## Erros a evitar

- Pular Persona — copy sem persona é redação
- Misturar dor com objeção (dor = problema; objeção = barreira pra comprar)
- Prova sem número (testimonial vago não convence)
- Mecanismo genérico (precisa ter nome próprio)
