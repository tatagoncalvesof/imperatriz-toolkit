# Modo: LANÇAMENTO

## Quando usar

- Planejar lançamento de produto/curso/mentoria
- Quebrar projeto grande em entregas
- Roadmap de feature
- Plano de campanha de marketing
- Cronograma de evento

## Estratégia

Mapa de lançamento é o **planejamento visual de execução**. Não é cronograma temporal puro — é estrutura de entregas com responsáveis.

3 movimentos:

1. **Marco final** (o que precisa estar pronto no D-day?)
2. **Fases reversas** (do final pro início)
3. **Entregas dentro de cada fase** (com responsável)

## Hierarquia base

```
NÍVEL 0: Nome do lançamento + data
NÍVEL 1: Fases (3-5)
NÍVEL 2: Entregas dentro de cada fase
NÍVEL 3: Tarefas/responsáveis/prazos
```

## Fases padrão (lançamento brasileiro)

```
ROOT: <Lançamento> — <data>
├── Pré-lançamento (4-6 sem antes)
│   ├── Oferta finalizada
│   ├── Página de vendas
│   ├── Sequência de e-mail
│   └── Criativos prontos
├── Aquecimento (2-3 sem antes)
│   ├── CPL #1
│   ├── CPL #2
│   ├── Aulas/conteúdo
│   └── Engajamento orgânico
├── Carrinho aberto (3-7 dias)
│   ├── Live de abertura
│   ├── Sequência diária
│   ├── Quebra de objeção
│   └── Última chamada
├── Pós-lançamento (1-2 sem depois)
│   ├── Onboarding
│   ├── Atendimento
│   ├── Análise de números
│   └── Retrospectiva
└── Métricas-meta
    ├── ROI alvo
    ├── # vendas
    └── Faturamento
```

## Templates alternativos

### Lançamento perpétuo (evergreen)

```
├── Captura (sempre ligado)
├── Nutrição (automação)
├── Oferta (gatilho de evento)
└── Pós-venda
```

### Evento ao vivo

```
├── Pré-evento
├── Dia D
├── Pós-evento imediato
└── Conversão pós-evento
```

### Feature/produto técnico

```
├── Discovery
├── Design
├── Build
├── Beta
├── Launch
└── Iteração pós-launch
```

## Adaptação ao input

- **Sem data definida:** pergunta. Lançamento sem data não é lançamento.
- **Time pequeno:** consolida fases (pré + aquecimento juntos)
- **Time grande:** explode com responsáveis específicos no nível 3
- **Lançamento já em andamento:** marca o que JÁ ESTÁ FEITO com ✓

## Anotações de prazo (formato no nó)

Use formato curto:
- `D-30` (30 dias antes)
- `D-7`
- `D-day`
- `D+3`
- `Q3` (quarter)

## Conexões cruzadas típicas

- Oferta ↔ Página de vendas (mudança de oferta = retrabalho de página)
- Aulas/CPL ↔ Sequência de e-mail (uma alimenta a outra)
- Carrinho aberto ↔ Pós-venda (entrega tem que estar pronta antes)

## Erros a evitar

- Lançamento sem fase de pós (vendeu, abandonou)
- Pulando o aquecimento (vai direto pra carrinho aberto = morte)
- Sem responsável definido (entrega sem dono = não acontece)
- Sem métricas (não saberá se deu certo)
